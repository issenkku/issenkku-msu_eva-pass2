# Support Achievement Score

## Goal

เพิ่มค่าผลลัพธ์สำหรับการประเมินสายสนับสนุนจากหนึ่งค่าเป็นสองค่า โดยคงสูตรและพฤติกรรมของเกณฑ์ Quantity และ Quality ไว้เหมือนเดิมทั้งหมด

## Scope

สายสนับสนุนมีค่าผลลัพธ์สองค่า:

1. `support_score_total` — ผลรวมคะแนนถ่วงน้ำหนักจากเกณฑ์สายสนับสนุน
2. `support_achievement_score` — คะแนนผลสัมฤทธิ์ของงาน คำนวณจาก `support_score_total / 5`

จำนวนระดับค่าเป้าหมายกำหนดคงที่เป็น `5` ไม่สร้างหน้าตั้งค่าและไม่รับค่าจาก request

## Calculation rules

- ใช้ผลรวม `weighted_score` เดิมเป็น `support_score_total`
- คำนวณ `support_achievement_score = support_score_total / 5`
- ปัดค่าที่บันทึกและแสดงเป็นทศนิยม 2 ตำแหน่ง
- หากคะแนนสายสนับสนุนว่างทั้งหมด ให้ทั้งสองค่าเป็น `0.00`
- “คะแนนรวมทั้งหมด” ยังคงใช้ `support_score_total` เพียงครั้งเดียว และไม่นำ `support_achievement_score` มารวมซ้ำ
- ไม่เปลี่ยนสูตร เพดานคะแนน การบันทึก หรือการแสดงผลของ Quantity และ Quality

## Persistence

เพิ่มคอลัมน์ทศนิยม `support_achievement_score` ในตาราง `reports` และเพิ่มใน model cast/fillable ให้สอดคล้องกับ `support_score_total`

`SupportScoreService` เป็นแหล่งคำนวณกลาง เมื่อบันทึกคะแนนสายสนับสนุนทุกสถานะ ทั้งบันทึกร่างและส่งผลประเมิน ระบบต้องคำนวณและบันทึกสองค่าภายใน transaction เดียวกัน เพื่อให้เมื่อส่งผลประเมินค่าทั้งคู่สอดคล้องกันเสมอ

ค่าคงที่จำนวนระดับเป้าหมาย `5` ต้องอยู่ในส่วนคำนวณคะแนนสายสนับสนุน ไม่กระจายเป็น magic number หลายตำแหน่ง ส่วน view และ JavaScript ใช้ค่าเดียวกันผ่าน data attribute หรือค่าที่ read model ส่งให้

## Summary display

เมื่อแบบประเมินมีเกณฑ์สายสนับสนุน กล่อง “สรุปคะแนนรวม” แสดงข้อมูลสายสนับสนุนสองรายการ:

- “ผลรวมคะแนนถ่วงน้ำหนัก” แสดง `support_score_total`
- การ์ด “คะแนนผลสัมฤทธิ์ของงาน” แสดง `support_achievement_score` พร้อมคำอธิบายว่า “ผลรวมคะแนนถ่วงน้ำหนัก ÷ 5”

ขณะผู้ใช้แก้คะแนนสายสนับสนุน JavaScript ต้องอัปเดตทั้งผลรวมคะแนนถ่วงน้ำหนัก คะแนนผลสัมฤทธิ์ และคะแนนรวมทั้งหมดทันที โดยคะแนนรวมใช้เฉพาะผลรวมคะแนนถ่วงน้ำหนัก

ถ้าแบบประเมินไม่มีเกณฑ์สายสนับสนุน จะไม่แสดงทั้งรายการผลรวมคะแนนถ่วงน้ำหนักและการ์ดคะแนนผลสัมฤทธิ์ กติกาการซ่อน/แสดง Quantity และ Quality ยังคงเดิม

## Data flow

1. ผู้ใช้กรอกค่าคะแนนของแต่ละเกณฑ์สายสนับสนุน
2. หน้าเว็บคำนวณ `weighted_score` รายเกณฑ์และผลรวมแบบเรียลไทม์
3. หน้าเว็บคำนวณคะแนนผลสัมฤทธิ์จากผลรวมหาร `5` เพื่อแสดงก่อนส่ง
4. เมื่อบันทึกหรือส่งผลประเมิน `SupportScoreService` คำนวณใหม่จากข้อมูลที่ผ่าน validation และบันทึกค่าทั้งสองลง `reports`
5. เมื่อเปิดหน้าอีกครั้ง read model ใช้ข้อมูลเกณฑ์เพื่อแสดงค่าที่ตรงกับข้อมูลที่บันทึก

## Validation and error handling

- ไม่รับ `support_achievement_score` จาก client เป็นค่าที่เชื่อถือได้ จึงไม่มีช่องกรอกและไม่มี validation rule สำหรับผู้ใช้
- Backend คำนวณค่าทั้งสองใหม่เสมอเพื่อป้องกันการแก้ request
- ใช้ validation และ transaction ของสายสนับสนุนเดิม หากรายการใดไม่ผ่าน validation จะไม่บันทึกทั้งสองค่าบางส่วน
- Migration กำหนดค่าเริ่มต้นเป็น `0.00` เพื่อรองรับรายงานเดิม

## Testing

- service test ยืนยันว่าผลรวม `4.30` บันทึกคะแนนผลสัมฤทธิ์ `0.86`
- service test ยืนยันค่าศูนย์เมื่อไม่มีคะแนน และยืนยันการคำนวณใหม่โดยไม่เชื่อค่าจาก client
- model/schema test ยืนยันคอลัมน์ ค่าเริ่มต้น และ decimal cast
- summary test ยืนยันการแสดงสองค่าเฉพาะเมื่อมีเกณฑ์สายสนับสนุน
- JavaScript contract/behavior test ยืนยันการอัปเดตสองค่าและยืนยันว่าคะแนนรวมยังใช้ผลรวมคะแนนถ่วงน้ำหนัก
- รันชุดทดสอบสายสนับสนุนและ test suite ทั้งหมดก่อนสรุปงาน

## Out of scope

- ไม่เปลี่ยน Quantity หรือ Quality
- ไม่ทำจำนวนระดับค่าเป้าหมายให้ตั้งค่าได้
- ไม่เพิ่มช่องให้ผู้ใช้กรอกคะแนนผลสัมฤทธิ์เอง
- ไม่เปลี่ยนสถานะ workflow สิทธิ์ผู้ใช้ หรือการส่งอีเมล
