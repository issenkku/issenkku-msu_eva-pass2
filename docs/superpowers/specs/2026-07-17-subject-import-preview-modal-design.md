# Subject Import Preview Modal Design

**วันที่:** 2026-07-17  
**สถานะ:** อนุมัติแนวทางแล้ว รอตรวจทานเอกสารก่อนจัดทำแผนดำเนินการ

## เป้าหมาย

เปลี่ยนผลตรวจสอบข้อมูลรายวิชาก่อนนำเข้าจากหน้าเต็มเป็น Modal ที่เปิดทับหน้าจัดการรายวิชา โดยคงกลไก token, Preview, Confirm และ Cancel เดิมไว้

ผู้ใช้ยังเริ่มงานจาก Modal “นำเข้าข้อมูลรายวิชา” เดิม เมื่อระบบอ่านไฟล์เสร็จจะกลับมาที่หน้ารายวิชาและเปิด Preview Modal อัตโนมัติ

## การตัดสินใจ

ใช้ **Server-rendered Preview Modal** โดยอ้าง Preview ผ่าน token ใน URL ของหน้ารายวิชา เช่น `subjects?import_preview=<token>`

แนวทางนี้ไม่เพิ่ม JSON API หรือ AJAX state ใหม่ และทำให้การ refresh หน้า การตรวจสิทธิ์เจ้าของ token การหมดอายุ และการยืนยันนำเข้ายังคงพึ่งกลไกฝั่งเซิร์ฟเวอร์ที่มีอยู่

หน้า Preview แบบเต็มเดิมจะไม่เป็นปลายทางหลักอีกต่อไป เส้นทางเดิมต้องนำผู้ใช้กลับมายังหน้ารายวิชาพร้อม token เพื่อรองรับลิงก์หรือ request ที่ยังอ้างเส้นทางเดิม

## ลำดับการทำงาน

1. ผู้ใช้เปิด Upload Modal จากหน้ารายวิชา
2. ผู้ใช้เลือกไฟล์ `.xlsx` และกด “ตรวจสอบข้อมูล”
3. เซิร์ฟเวอร์อ่านไฟล์ สร้าง Preview snapshot และ token อายุ 30 นาทีเหมือนเดิม
4. เซิร์ฟเวอร์ redirect ไปหน้ารายวิชาพร้อม query `import_preview`
5. หน้ารายวิชาตรวจ token ตามผู้ใช้ที่ login และ render Preview Modal
6. JavaScript เปิด Preview Modal อัตโนมัติหลัง DOM พร้อม
7. ผู้ใช้เลือกข้อมูลซ้ำที่ต้องการอัปเดตแล้ว Confirm หรือ Cancel
8. Confirm หรือ Cancel ใช้ route เดิม ล้าง token ตามกติกาเดิม และ redirect กลับหน้ารายวิชาโดยไม่มี query Preview

## โครงสร้าง Preview Modal

### Dialog

- ใช้ Bootstrap Modal ขนาด `modal-xl`
- ใช้ `modal-dialog-scrollable` เพื่อให้ header และ footer อยู่กับที่ ส่วนตารางเลื่อนภายใน
- ใช้รูปแบบเต็มจอบนหน้าจอขนาดเล็ก
- ชื่อ Modal คือ “ตรวจสอบข้อมูลก่อนนำเข้า”
- คำอธิบายสั้นคือ “ตรวจรายการใหม่และเลือกรายการซ้ำที่ต้องการอัปเดต”

### แถบสถานะแบบย่อ

ไม่แสดงการ์ดสรุปขนาดใหญ่สี่ใบ ให้แสดงบรรทัดสถานะขนาดเล็กด้านบนของเนื้อหาแทน โดยมีชื่อสถานะและจำนวนครบสี่กลุ่ม:

- เพิ่มใหม่ `<จำนวน>`
- ข้อมูลซ้ำที่เปลี่ยน `<จำนวน>`
- ไม่เปลี่ยนแปลง `<จำนวน>`
- ข้อผิดพลาด `<จำนวน>`

สถานะใช้ข้อความเป็นข้อมูลหลัก อาจใช้สีหรือ badge เพื่อช่วยแยกกลุ่มได้ แต่ความหมายต้องไม่พึ่งสีเพียงอย่างเดียว และไม่สร้างพื้นที่ขนาดใหญ่แบบการ์ดเดิม

### เนื้อหา

นำตารางเดิมมาใช้ใน Modal:

- ตารางข้อผิดพลาด แสดงเมื่อมี error
- ตารางข้อมูลซ้ำที่เปลี่ยนแปลง พร้อม checkbox และปุ่มเลือกทั้งหมด/ไม่เลือกทั้งหมด
- ตารางเพิ่มใหม่
- ตารางไม่เปลี่ยนแปลง

แต่ละตารางยังมีหัวตาราง, caption สำหรับ screen reader และ empty state เหมือนเดิม ตารางเลื่อนแนวนอนได้เมื่อพื้นที่ไม่พอ

### Footer และการปิด

- ปุ่ม “ยกเลิก” เรียก Cancel route และลบ Preview token
- ปุ่ม “ยืนยันการนำเข้า” เรียก Confirm route เดิม
- ปุ่มยืนยัน disabled เมื่อ Preview มีข้อผิดพลาด
- ปุ่มปิดที่ header ทำหน้าที่เดียวกับ Cancel เพื่อไม่ให้ snapshot ค้างโดยผู้ใช้เข้าใจว่า workflow ถูกยกเลิกแล้ว
- ป้องกันการปิดด้วย backdrop หรือ Escape ที่จะซ่อน Modal โดยไม่ยกเลิก token ผู้ใช้ต้องเลือก Cancel/ปิดอย่างชัดเจน

## การเชื่อมต่อฝั่งเซิร์ฟเวอร์

`SubjectImportController::storePreview()` ยังคงสร้าง snapshot เหมือนเดิม แต่เปลี่ยนปลายทาง redirect เป็นหน้ารายวิชาพร้อม query token

`SubjectController::index()` อ่าน query token ผ่าน `SubjectImportSnapshotStore`, ตรวจว่า snapshot เป็นของผู้ใช้ปัจจุบัน และส่ง `importPreview` กับ `importPreviewToken` ให้ view เมื่อ token ถูกต้อง

หาก token ไม่มีอยู่ หมดอายุ หรือไม่ใช่ของผู้ใช้ปัจจุบัน ระบบตอบ 404 และไม่เปิดเผยข้อมูล Preview

Confirm, Cancel, stale-preview protection, database transaction และ result message หลังนำเข้าไม่เปลี่ยนแปลง

## Accessibility และพฤติกรรม Focus

- Modal มี `aria-labelledby` เชื่อมกับหัวข้อที่ไม่ซ้ำกัน
- เมื่อเปิด Modal focus ย้ายไปที่หัวข้อหรือ control แรกที่ใช้งานได้
- Bootstrap focus trap เก็บ focus อยู่ภายใน Modal
- หลัง Cancel และกลับหน้ารายวิชา focus เริ่มตาม navigation ปกติของหน้า
- ปุ่ม icon-only มี accessible name ภาษาไทย
- สถานะทั้งสี่อ่านเป็นข้อความและจำนวน ไม่ใช้สีแทนความหมาย
- ปุ่มยืนยันที่ disabled ต้องยังมีข้อความอธิบายข้อผิดพลาดอยู่ในเนื้อหา
- ตารางรักษา `scope`, caption และโครงสร้าง semantic เดิม

## การจัดการข้อผิดพลาด

- File validation error ยังคงเปิด Upload Modal เดิมพร้อมข้อความผิดพลาด
- Row validation error เปิด Preview Modal และแสดงตารางข้อผิดพลาด โดยปิดการยืนยัน
- Token หมดอายุหรือไม่มีสิทธิ์ตอบ 404
- Preview ล้าสมัยระหว่าง Confirm ใช้ข้อความ error เดิมและกลับหน้ารายวิชา
- Cancel และปุ่มปิดลบ token ก่อนกลับหน้ารายวิชา

## สิ่งที่ไม่อยู่ในขอบเขต

- ไม่เปลี่ยนกติกาการอ่านหรือตรวจ Excel
- ไม่เปลี่ยนการตรวจข้อมูลซ้ำหรือการเลือกอัปเดต
- ไม่เปลี่ยนฐานข้อมูลหรืออายุ token
- ไม่เพิ่ม AJAX upload, JSON Preview API หรือ polling
- ไม่เปลี่ยน Upload Modal, Template หรือ Export
- ไม่แสดงการ์ดสรุปขนาดใหญ่ใน Preview Modal

## การทดสอบ

เพิ่มหรือปรับชุดทดสอบให้ครอบคลุม:

1. Upload สำเร็จ redirect ไปหน้ารายวิชาพร้อม query token
2. หน้ารายวิชาที่มี token ถูกต้อง render Preview Modal และเปิดอัตโนมัติ
3. Preview Modal แสดงสถานะทั้งสี่พร้อมจำนวนแบบย่อ และไม่มี class/markup ของ summary card เดิม
4. ตาราง error, changed, new และ unchanged ยัง render ครบ
5. ปุ่ม Confirm disabled เมื่อมี error และ enabled เมื่อไม่มี error
6. ปุ่ม Cancel และปุ่มปิดส่ง request ไป Cancel route
7. token ของผู้ใช้อื่นหรือ token หมดอายุไม่แสดง Preview และตอบ 404
8. เส้นทาง Preview เดิม redirect ไปหน้ารายวิชาพร้อม token
9. Select all/none และ checkbox รายการซ้ำยังทำงาน
10. Modal มี label, focus behavior, scroll และข้อกำหนดการปิดที่ตรวจสอบได้จาก view contract

## เกณฑ์ยอมรับ

- หลังอัปโหลดไฟล์ ผู้ใช้เห็น Preview เป็น Modal ทับหน้ารายวิชา ไม่เห็นหน้า Preview แบบเต็ม
- ด้านบน Modal แสดงสถานะทั้งสี่และจำนวนในรูปแบบย่อ ไม่มีการ์ดสรุปขนาดใหญ่
- ตารางและการเลือกข้อมูลซ้ำทำงานเหมือนเดิม
- Confirm และ Cancel ใช้ token และผลลัพธ์เดิมอย่างปลอดภัย
- Modal ใช้งานได้ด้วย keyboard, screen reader และหน้าจอขนาดเล็ก
- Refresh หน้าที่มี token เปิด Preview Modal เดิมได้ตราบใดที่ token ยังไม่หมดอายุ
