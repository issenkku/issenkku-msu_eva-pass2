# Support Criteria Activity Entries Design

วันที่: 2026-07-21
สถานะ: อนุมัติแนวทางแล้ว รอตรวจทานเอกสารก่อนพัฒนา

## ปัญหา

เกณฑ์สายสนับสนุนปัจจุบันมีข้อความ “กิจกรรม/โครงการ/งาน” ที่ Admin กำหนดใน Template เท่านั้น บางเกณฑ์ต้องเปิดให้ผู้ถูกประเมินเพิ่มรายละเอียดกิจกรรมหรือโครงการของตนได้หลายรายการ ขณะที่เกณฑ์อื่นต้องแสดงเฉพาะข้อความของ Admin

## เป้าหมาย

- Admin กำหนดได้เป็นรายเกณฑ์ว่าอนุญาตให้ผู้ถูกประเมินเพิ่มกิจกรรม/โครงการได้หรือไม่
- เมื่อเปิดใช้ ผู้ถูกประเมินเพิ่ม Rich Text ได้หลายรายการโดยไม่บังคับว่าต้องมีรายการ
- ผู้ประเมินทุก Role แก้ไขรายการได้โดยต้องให้เหตุผลและมีประวัติ
- คงคะแนน น้ำหนัก หลักฐาน Modal และ Flow การบันทึก/ยืนยันส่งเดิม

## ขอบเขตและคำศัพท์

- **ข้อความกิจกรรมของ Admin**: ค่า `activity_name` ใน `support_criterias` ใช้เป็นหัวข้อหรือคำอธิบาย ไม่นับเป็นรายการของผู้ถูกประเมิน
- **รายการกิจกรรม**: Rich Text ที่ผู้ถูกประเมินเพิ่มภายใต้เกณฑ์หนึ่งในรายงานหนึ่ง
- Checkbox และรายการกิจกรรนี้เป็นส่วนของเกณฑ์สายสนับสนุนเท่านั้น

## การตั้งค่าของ Admin

- เพิ่ม Checkbox ในแต่ละ `support_criteria_block` ชื่อ “อนุญาตให้ผู้ถูกประเมินเพิ่มกิจกรรม/โครงการ”
- ค่าเริ่มต้นเป็นไม่ติ๊ก
- เก็บค่าใน `support_criterias.allow_activity_entries` ชนิด boolean และส่ง/โหลดค่าผ่าน create, edit, clone และ API ของ Template เดิม
- Rich Text “กิจกรรม/โครงการ/งาน” ของ Admin ทำงานเหมือนเดิมทุกประการ

## โครงสร้างข้อมูล

### `support_activity_entries`

เก็บรายการ Rich Text แยกตามรายงานและเกณฑ์:

- `id`
- `report_id` foreign key ไป `reports`
- `support_criteria_id` foreign key ไป `support_criterias`
- `sequence` ลำดับภายในเกณฑ์
- `content` ชนิด text
- `created_by` และ `updated_by` foreign key ไป `users`
- timestamps
- index บน `report_id`, `support_criteria_id`, `sequence`

### `support_activity_entry_histories`

เก็บประวัติเฉพาะการแก้ไขโดยผู้ประเมิน:

- `id`
- `support_activity_entry_id` foreign key ไป `support_activity_entries`
- `previous_content` และ `new_content` ชนิด text
- `reason` ชนิด text
- `modified_by` foreign key ไป `users`
- `modified_by_role`
- timestamps

การลบรายงานหรือเกณฑ์ให้ cascade มายังรายการและประวัติ การปิด Checkbox ไม่ลบข้อมูลเดิม; รายการจะไม่แสดงจนกว่าจะเปิด Checkbox อีกครั้ง

## UI ของผู้ถูกประเมิน

- ถ้า Checkbox ไม่ถูกติ๊ก คอลัมน์กิจกรรมแสดงเฉพาะ Rich Text ของ Admin
- ถ้า Checkbox ถูกติ๊ก ภายใต้ข้อความ Admin แสดงรายการที่มีอยู่และปุ่ม “+ เพิ่มกิจกรรม/โครงการ”
- ปุ่มเปิด Modal ที่ใช้ Rich Text Editor แบบเดียวกับ Admin
- ผู้ถูกประเมินเพิ่ม แก้ไข และลบรายการได้เมื่อรายงานอยู่ในสถานะที่ผู้ถูกประเมินแก้ไขได้ตาม Flow เดิม รายการใหม่ต่อท้ายตามลำดับการเพิ่ม
- รายการเป็นตัวเลือก ผู้ถูกประเมินบันทึกหรือยืนยันส่งได้แม้ไม่มีรายการ

## UI ของผู้ประเมิน

- แสดงรายการในคอลัมน์กิจกรรมภายใต้ข้อความของ Admin เหมือนมุมมองผู้ถูกประเมิน
- ผู้ประเมินไม่สามารถเพิ่มหรือลบรายการ
- ผู้ประเมินแก้ไข Rich Text ของรายการเดิมได้ในช่วง Role/สถานะที่แก้ไขผลประเมินได้ตาม Flow เดิม
- ทุกการแก้ไขที่ข้อความเปลี่ยนต้องกรอกเหตุผล และแสดงประวัติให้ตรวจสอบย้อนหลังได้

## การบันทึกและ Flow

- การเพิ่ม/แก้ไข/ลบใน UI เก็บไว้ในหน้าจอก่อน
- ลงฐานข้อมูลพร้อมการกด “บันทึกฉบับร่าง” หรือ “ยืนยันและส่ง” ตาม Flow เดิม
- payload ของแต่ละ `support_list` มี `activity_entries` แบบ nested array โดยรายการเดิมส่ง `id` และรายการใหม่ไม่มี `id`
- ฝั่ง Server ตรวจว่ารายงานเป็นของผู้ใช้/ผู้ประเมินตาม Role, เกณฑ์อยู่ใน Template ของรายงาน และสถานะอนุญาตให้ Role นั้นแก้ไข
- ผู้ถูกประเมินสร้าง แก้ไข และลบได้โดยไม่เก็บประวัติหรือบังคับเหตุผล
- ผู้ประเมินส่งได้เฉพาะ `id`, `content` และ `modification_reason` สำหรับรายการเดิม; ห้ามสร้าง ลบ หรือจัดลำดับ
- สร้างประวัติเฉพาะเมื่อผู้ประเมินส่งข้อความที่เปลี่ยนไปพร้อมเหตุผลที่มีข้อความจริง
- ใช้ transaction เดียวกับการบันทึกคะแนนสายสนับสนุนเพื่อป้องกันข้อมูลบางส่วนถูกบันทึก

## Validation และความปลอดภัย

- รายการทั้งหมดเป็นตัวเลือก แต่เมื่อผู้ใช้สร้างรายการแล้ว `content` ต้องมีข้อความที่มองเห็นได้จริง ไม่รับเฉพาะ tag ว่าง
- ทำความสะอาด Rich Text ด้วย `SafeHtml` แบบเดียวกับข้อความของ Admin ก่อนแสดงผล
- ไม่รับรายการใหม่หรือการลบจากผู้ประเมิน
- ไม่อนุญาตให้เพิ่มรายการใหม่หาก `allow_activity_entries` เป็น false
- รายการ `id` ที่ส่งมาต้องอยู่ใน report และ support criterion เดียวกัน
- การแก้ไขของผู้ประเมินที่ไม่มีเหตุผลหรือเหตุผลเป็นช่องว่างไม่สามารถบันทึกได้

## สิ่งที่ไม่เปลี่ยน

- สูตรคะแนนถ่วงน้ำหนัก ค่าคะแนนที่ได้ และน้ำหนัก
- การบังคับหลักฐานระดับเกณฑ์ และลิงก์หลักฐานเดิม
- Modal จัดการคะแนน/หลักฐาน และ comment ของแต่ละ Role
- การสร้างประวัติคะแนนเดิม
- สถานะและการส่งต่อระหว่างผู้ถูกประเมิน ผู้ประเมิน กรรมการ และผู้บริหาร

## การทดสอบ

- migration, model relations, fillable/casts และ cascade behavior
- Admin create/edit/clone เก็บและโหลด Checkbox ได้
- เกณฑ์ที่ไม่ติ๊กแสดงเฉพาะข้อความ Admin และไม่ส่งรายการใหม่ได้
- ผู้ถูกประเมินส่งได้โดยไม่มีรายการ และเพิ่ม/แก้ไข/ลบได้เมื่อเปิด Checkbox
- Rich Text ว่างถูกปฏิเสธ และเนื้อหาอันตรายไม่ถูกแสดง
- ผู้ประเมินสร้าง/ลบ/จัดลำดับไม่ได้ แก้ไขได้เมื่อมีเหตุผล และการแก้สร้างประวัติครบถ้วน
- ผู้ถูกประเมินแก้ไขโดยไม่สร้างประวัติ
- โหมดตารางและการ์ดแสดงรายการตรงกัน
- focused tests, full PHP suite, Rich Text lifecycle tests, Blade cache, Vite build และ `git diff --check`

## เกณฑ์สำเร็จ

Admin เปิดหรือปิดความสามารถเพิ่มกิจกรรมรายเกณฑ์ได้ เกณฑ์ที่ปิดแสดงเฉพาะหัวข้อของ Admin เกณฑ์ที่เปิดให้ผู้ถูกประเมินจัดการ Rich Text เสริมได้หลายรายการแบบไม่บังคับ ผู้ประเมินแก้ไขรายการได้พร้อมเหตุผลและประวัติ โดยไม่กระทบคะแนน น้ำหนัก หลักฐาน หรือ Flow การประเมินเดิม
