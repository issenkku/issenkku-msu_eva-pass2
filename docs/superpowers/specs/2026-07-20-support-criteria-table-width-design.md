# Support Criteria Table Width Design

วันที่: 2026-07-20  
สถานะ: อนุมัติแนวทางแล้ว รอตรวจทานเอกสารก่อนพัฒนา

## ปัญหา

หน้าประเมินปัจจุบันจำกัดความกว้างด้วย `max-w-4xl` ประมาณ 896px ขณะที่ตารางเกณฑ์สายสนับสนุนมี 9 คอลัมน์ ทำให้หัวตารางและข้อมูลยาวถูกบีบเป็นหลายบรรทัด แม้ผู้ใช้เปิดบนจอกว้าง

## เป้าหมาย

ใช้พื้นที่จอกว้างให้เหมาะกับตาราง โดยยังคงการเลื่อนแนวนอนบนจอขนาดกลางและรูปแบบการ์ดบนมือถือ ไม่เปลี่ยน Modal, payload, validation หรือ Flow การบันทึก

## ขอบเขตหน้า

ขยาย wrapper ของหน้าประเมินที่ใช้ component เกณฑ์สายสนับสนุนร่วมกัน:

- ผู้ถูกประเมิน
- ผู้ประเมิน
- กรรมการ
- ผู้บริหาร
- หน้าผู้ดูแลระบบที่ใช้ฟอร์มประเมินเดียวกัน

wrapper เปลี่ยนจาก `max-w-4xl` เป็น `w-full max-w-7xl` และยังคง `mx-auto space-y-6`

## ตารางเดสก์ท็อป

- ตารางใช้ `min-w-[1180px] w-full` ภายใน wrapper ที่มี `overflow-x-auto`
- ยกเลิก `table-fixed` เพื่อให้ browser แจกพื้นที่เพิ่มเติมตามความยาวเนื้อหา
- กำหนดพื้นที่ขั้นต่ำให้คอลัมน์ข้อความ:
  - กิจกรรม/โครงการ/งาน: `min-w-[240px]`
  - ตัวชี้วัด/เกณฑ์การประเมิน: `min-w-[360px]`
- กำหนดพื้นที่ขั้นต่ำให้คอลัมน์ค่าต่าง ๆ:
  - ระดับค่าเป้าหมาย: `min-w-[110px]`
  - น้ำหนัก: `min-w-[80px]`
  - ค่าคะแนนที่ได้: `min-w-[100px]`
  - คะแนนถ่วงน้ำหนัก: `min-w-[120px]`
  - หลักฐาน: `min-w-[90px]`
  - จัดการ: `min-w-[100px]` เฉพาะโหมดแก้ไข
- ลำดับคงความกว้างประมาณ 64px
- ข้อมูลยาวยังตัดบรรทัดได้ตามธรรมชาติ แต่ไม่ถูกบีบให้เหลือพื้นที่แคบผิดปกติ

## Responsive

- ตั้งแต่ `md` ขึ้นไปใช้ตารางและเลื่อนแนวนอนเมื่อ viewport แคบกว่า 1180px
- ต่ำกว่า `md` ใช้การ์ดเดิม
- ไม่เพิ่ม horizontal overflow ให้ทั้งหน้า แถบเลื่อนอยู่เฉพาะ container ของตาราง
- Modal คง `max-w-3xl` เพราะเป็นฟอร์มรายการเดียวและไม่ต้องขยายตามตาราง

## สิ่งที่ไม่เปลี่ยน

- ข้อมูลและลำดับคอลัมน์
- การเปิด Modal จากคอลัมน์จัดการหรือหลักฐาน
- คะแนน หลักฐาน เหตุผล ประวัติ และสิทธิ์แต่ละ Role
- การคำนวณและการบันทึกฝั่ง Server
- รูปแบบมือถือ

## การทดสอบ

- หน้าประเมินทุก wrapper ที่อยู่ในขอบเขตใช้ `max-w-7xl` และไม่ใช้ `max-w-4xl`
- ตารางมี `min-w-[1180px]` และไม่มี `table-fixed`
- คอลัมน์กิจกรรมและตัวชี้วัดมีความกว้างขั้นต่ำตามแบบ
- โหมดแก้ไขและอ่านอย่างเดียวยังคงแสดงคอลัมน์ตามสิทธิ์
- Blade cache, focused view tests, full PHP suite และ Vite build ผ่าน

## เกณฑ์สำเร็จ

บนจอกว้าง ตารางเกณฑ์สายสนับสนุนใช้พื้นที่เพิ่มขึ้นอย่างเห็นได้ชัด ข้อความกิจกรรมและตัวชี้วัดอ่านง่ายขึ้นโดยไม่บีบคอลัมน์ตัวเลข ส่วนจอขนาดกลางและมือถือยังใช้งานได้โดยไม่มีผลกระทบต่อ Flow เดิม
