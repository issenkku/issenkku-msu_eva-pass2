# Score Summary Visible Criteria

## Goal

ปรับกล่อง “สรุปคะแนนรวม” ให้แสดงเฉพาะประเภทคะแนนที่มีเกณฑ์อยู่ในแบบประเมินนั้น แทนการแสดง Quantity, Quality และสายสนับสนุนครบทุกประเภทแบบตายตัว

## Display rules

- แสดง “คะแนนด้านปริมาณ (Quantity)” เมื่อมี `quantity_items` อย่างน้อยหนึ่งรายการในแบบประเมิน
- แสดง “คะแนนด้านคุณภาพ (Quality)” เมื่อมี `quality_items` อย่างน้อยหนึ่งรายการในแบบประเมิน
- แสดง “คะแนนสายสนับสนุน” เมื่อมี `support_items` อย่างน้อยหนึ่งรายการในแบบประเมิน
- ประเภทที่มีเกณฑ์ต้องแสดงแม้คะแนนปัจจุบันเป็น `0.00` เพราะอาจเป็นเกณฑ์ที่ยังไม่ได้กรอกหรือมีคะแนนเป็นศูนย์จริง
- ประเภทที่ไม่มีเกณฑ์ต้องไม่แสดงบรรทัดคะแนน แม้โครงสร้างสรุปคะแนนจะมีค่าเริ่มต้นเป็นศูนย์
- “คะแนนรวมทั้งหมด” ยังคงแสดงและรวมคะแนนเฉพาะประเภทที่มีเกณฑ์ตามสูตรเดิม
- ใช้กติกาเดียวกันในหน้าของผู้รับการประเมิน ผู้ประเมิน และผู้อนุมัติ

## Design

ให้ `EvaluationScoreSummary` ตรวจการมีอยู่ของรายการเกณฑ์ขณะคำนวณคะแนน และส่งสถานะ `has_quantity`, `has_quality` และ `has_support` ไปพร้อมค่าคะแนนเดิม เพื่อให้สถานะการแสดงผลมาจากแหล่งข้อมูลเดียวกับคะแนน

Blade summary render แต่ละบรรทัดด้วยสถานะดังกล่าว โดยไม่ใช้ค่าคะแนนเป็นตัวตัดสิน เพราะคะแนน `0.00` ไม่ได้แปลว่าไม่มีเกณฑ์ สำหรับ component ที่ยังคำนวณ summary ภายใน view ให้ตรวจรายการเกณฑ์ด้วยกติกาเดียวกัน หรือปรับไปใช้ summary object ร่วมเมื่อทำได้โดยไม่ขยายขอบเขตเกินจำเป็น

JavaScript ที่อัปเดตคะแนนระหว่างกรอกต้องรองรับกรณี element ของประเภทที่ไม่มีเกณฑ์ไม่ได้ถูก render และต้องไม่สร้างบรรทัดประเภทนั้นขึ้นมาใหม่

## Data flow

1. ระบบอ่าน `quantity_items`, `quality_items` และ `support_items` จากทุก evaluation list ใน `categoryItems`
2. ระบบคำนวณคะแนนด้วยสูตรและเพดานคะแนนเดิม พร้อมบันทึกว่าพบเกณฑ์แต่ละประเภทหรือไม่
3. View แสดงเฉพาะบรรทัดที่สถานะ `has_*` เป็นจริง
4. Script อัปเดตเฉพาะบรรทัดที่มีอยู่ และอัปเดตคะแนนรวมตามเดิม

## Empty state

หากแบบประเมินไม่มีเกณฑ์คะแนนทั้งสามประเภท ให้คงหัวข้อและ “คะแนนรวมทั้งหมด” เป็น `0.00` โดยไม่แสดงบรรทัดประเภทคะแนนที่ว่าง เพื่อให้หน้าจอยังมีผลสรุปที่แน่นอนและไม่เกิดกล่องว่างทั้งหมด

## Testing

- เพิ่ม unit test ให้ summary ระบุสถานะการมีเกณฑ์แต่ละประเภทจากรายการจริง โดยไม่อิงค่าคะแนน
- เพิ่ม view test ว่าประเภทที่ไม่มีเกณฑ์ถูกซ่อน และประเภทที่มีเกณฑ์แต่คะแนนเป็นศูนย์ยังแสดง
- ตรวจหน้าสรุปของทุกบทบาทที่ใช้ implementation ต่างกันให้เป็นไปตามกติกาเดียวกัน
- รัน focused tests, test suite ที่เกี่ยวข้อง และ `git diff --check` ก่อนสรุปงาน

## Out of scope

- ไม่เปลี่ยนสูตรคำนวณคะแนน เพดานคะแนน หรือการบันทึกคะแนน
- ไม่เปลี่ยนโครงสร้างเกณฑ์และสิทธิ์ของแต่ละบทบาท
- ไม่เปลี่ยนหน้าตาหรือข้อความอื่นนอกกล่องสรุปคะแนน
