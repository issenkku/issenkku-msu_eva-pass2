# Independent Subject Credit Values Design

**วันที่:** 2026-07-17  
**สถานะ:** อนุมัติแนวทางแล้ว รอตรวจทานเอกสารก่อนจัดทำแผนดำเนินการ

เอกสารนี้แทนที่เฉพาะกติกาที่บังคับให้หน่วยกิตรวมเท่ากับผลรวมของหน่วยกิตย่อยใน `2026-07-17-subject-excel-import-design.md` ข้อกำหนดส่วนอื่นของการนำเข้า Excel ยังคงเดิม

## เป้าหมาย

ปรับกติกาหน่วยกิตรายวิชาให้ตัวเลขทั้งสี่ช่องเป็นข้อมูลอิสระ ระบบบันทึกและนำแต่ละค่าไปใช้ตามประเภทโดยไม่คำนวณหรือบังคับความสัมพันธ์ระหว่างกัน

ช่องข้อมูลที่อยู่ในขอบเขตคือ:

- `credits` — หน่วยกิตรวม
- `lecture_credits` — หน่วยกิตบรรยาย
- `lab_credits` — หน่วยกิตปฏิบัติ
- `self_study_credits` — หน่วยกิตศึกษาด้วยตนเอง

## ปัญหาปัจจุบัน

การนำเข้า Excel ปฏิเสธแถวที่ `credits` ไม่เท่ากับผลรวมของอีกสามช่อง ขณะเดียวกันฟอร์มเพิ่มและแก้ไขรายวิชาคำนวณ `credits` อัตโนมัติเมื่อผู้ใช้เปลี่ยนช่องย่อย ทำให้ข้อมูลอย่าง `3, 3, 0, 6` ไม่สามารถเก็บตรงตามต้นทางได้ แม้ระบบต้องการนำค่าแต่ละประเภทไปใช้อย่างอิสระ

## การตัดสินใจ

ใช้แนวทาง **แยกค่าหน่วยกิตทั้งสี่ช่องเป็นอิสระทั้งหมด**:

- ไม่คำนวณ `credits` จากช่องย่อย
- ไม่เปรียบเทียบ `credits` กับผลรวมของช่องย่อย
- ไม่แสดงคำเตือนเมื่อค่าทั้งสี่ไม่สัมพันธ์กัน
- บันทึกแต่ละค่าตรงตามที่ผู้ใช้กรอกหรือข้อมูลใน Excel

กติกาที่คงไว้สำหรับทุกช่อง:

- ต้องมีค่า
- ต้องเป็นจำนวนเต็ม
- ต้องมีค่าตั้งแต่ `0` ขึ้นไป

## ขอบเขตการเปลี่ยนแปลง

### การนำเข้า Excel

ตัวตรวจสอบแต่ละแถวจะตรวจทั้งสี่ช่องแยกกันเท่านั้น แถวที่มีค่า `3, 3, 0, 6` หรือค่าชุดอื่นที่ผลรวมไม่ตรงกันจะผ่านการตรวจสอบ หากทุกค่าเป็นจำนวนเต็มตั้งแต่ศูนย์ขึ้นไป

หน้าตรวจสอบก่อนนำเข้าจะไม่สร้างข้อผิดพลาด `หน่วยกิตรวมต้องเท่ากับผลรวมของหน่วยกิตย่อย` อีกต่อไป ส่วนข้อผิดพลาดของค่าที่ว่าง ไม่ใช่จำนวนเต็ม หรือติดลบยังแสดงตามเดิม

### ฟอร์มเพิ่มและแก้ไขรายวิชา

ยกเลิก JavaScript ที่แก้ค่า `credits` อัตโนมัติเมื่อผู้ใช้กรอก `lecture_credits`, `lab_credits` หรือ `self_study_credits` ทั้งในหน้าจัดการรายวิชาและจุดที่เปิดฟอร์มรายวิชาจากหน้าผู้รับการประเมิน

ผู้ใช้กรอกและแก้ไขทั้งสี่ช่องได้โดยตรง การตรวจสอบฝั่งหน้าเว็บและเซิร์ฟเวอร์ยังบังคับให้แต่ละช่องเป็นจำนวนเต็มตั้งแต่ศูนย์ขึ้นไป

### การจัดเก็บและการใช้งานภายหลัง

ไม่มีการเปลี่ยน schema ฐานข้อมูล ชื่อคอลัมน์ หรือโค้ดที่เลือกค่าไปใช้ในสูตรภาระงาน ระบบส่วนที่ต้องการหน่วยกิตรวม บรรยาย ปฏิบัติ หรือศึกษาด้วยตนเองจะอ่านค่าจากคอลัมน์เดิมของประเภทนั้นโดยตรง

## สิ่งที่ไม่อยู่ในขอบเขต

- ไม่ทำให้ช่องหน่วยกิตใดเป็น optional
- ไม่รองรับเลขทศนิยม
- ไม่เปลี่ยนค่าข้อมูลรายวิชาที่บันทึกไว้แล้ว
- ไม่ลบคอลัมน์หน่วยกิตย่อย
- ไม่เปลี่ยนสูตรภาระงานหรือหลักเกณฑ์การประเมิน
- ไม่เปลี่ยนรูปแบบไฟล์ Excel หรือชื่อหัวคอลัมน์

## การจัดการข้อผิดพลาด

ข้อผิดพลาดจะผูกกับช่องที่มีปัญหาโดยตรง เช่น:

- ช่องว่าง — ต้องกรอกข้อมูล
- ตัวอักษรหรือเลขทศนิยม — ต้องเป็นจำนวนเต็ม
- จำนวนติดลบ — ต้องมีค่าตั้งแต่ 0 ขึ้นไป

ระบบจะไม่มีข้อผิดพลาดระดับข้ามช่องสำหรับความไม่ตรงกันของหน่วยกิต

## การทดสอบ

เพิ่มหรือปรับชุดทดสอบให้ครอบคลุม:

1. ตัวตรวจ Excel ยอมรับ `credits = 3`, `lecture_credits = 3`, `lab_credits = 0`, `self_study_credits = 6`
2. Preview การนำเข้าไม่มีข้อผิดพลาดเรื่องผลรวมสำหรับค่าที่ไม่ตรงกัน
3. ฟอร์มเพิ่มรายวิชาบันทึกค่าทั้งสี่ตามที่ส่งมาโดยไม่เปลี่ยน `credits`
4. ฟอร์มแก้ไขรายวิชาบันทึกค่าทั้งสี่ตามที่ส่งมาโดยไม่เปลี่ยน `credits`
5. JavaScript ของทั้งสองจุดไม่คำนวณหรือเขียนทับ `credits` จากช่องย่อย
6. ค่าที่ว่าง ไม่เป็นจำนวนเต็ม หรือติดลบยังถูกปฏิเสธ

## เกณฑ์ยอมรับ

- Excel ที่มีค่าหน่วยกิต `3, 3, 0, 6` ผ่าน Preview และนำเข้าได้
- การแก้ช่องย่อยในฟอร์มไม่เปลี่ยนช่องหน่วยกิตรวม
- หลังบันทึก ค่าในฐานข้อมูลตรงกับค่าทั้งสี่ที่ผู้ใช้กรอก
- ไม่มีข้อความแจ้งเตือนหรือข้อผิดพลาดเกี่ยวกับผลรวมหน่วยกิต
- กติกาจำนวนเต็มตั้งแต่ศูนย์ขึ้นไปยังทำงานครบทุกช่อง
