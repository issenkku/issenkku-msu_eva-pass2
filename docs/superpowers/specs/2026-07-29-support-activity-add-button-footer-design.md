# Support Activity Add Button Footer Design

วันที่: 2026-07-29
สถานะ: อนุมัติแนวทางแล้ว รอตรวจทานเอกสารก่อนพัฒนา

## ปัญหา

ใน Modal จัดการเกณฑ์สายสนับสนุน ปุ่ม `+ เพิ่มกิจกรรม/โครงการ` อยู่แถวเดียวกับหัวข้อ `กิจกรรม/โครงการเพิ่มเติม` และชิดขวาด้านบน ผู้ใช้ต้องเลื่อนผ่านรายการกิจกรรมและหลักฐานก่อนจึงจะเห็นจุดสิ้นสุดของข้อมูล แต่ต้องย้อนกลับขึ้นไปกดปุ่มเพื่อเพิ่มรายการใหม่ ทำให้ตำแหน่งปุ่มไม่สอดคล้องกับลำดับการกรอกข้อมูลและอาจทำให้สับสน

## แนวทางที่เลือก

- ย้ายปุ่ม `+ เพิ่มกิจกรรม/โครงการ` ออกจากแถวหัวข้อ
- วางปุ่มเป็น footer ชิดซ้ายภายในส่วน `กิจกรรม/โครงการเพิ่มเติม`
- footer อยู่หลัง container ของรายการ จึงแสดงใต้การ์ดรายการสุดท้ายและใต้ส่วนลิงก์หลักฐานของรายการนั้น
- หากยังไม่มีรายการ ปุ่มจะแสดงใต้ข้อความสถานะว่าง
- เมื่อเพิ่มหรือลบรายการ ปุ่มยังคงอยู่ท้ายรายการโดยไม่ต้องย้ายด้วย JavaScript

## สิ่งที่ไม่เปลี่ยน

- ข้อความ สี ขนาด hover และ focus state ของปุ่ม
- `data-add-support-activity` และพฤติกรรมการเพิ่มรายการเดิม
- สิทธิ์การมองเห็นปุ่ม: แสดงเฉพาะผู้ถูกประเมินที่แก้ไขกิจกรรมได้
- โครงสร้างข้อมูล validation การบันทึก และการลบรายการ
- ปุ่ม `+ เพิ่มโครงการในข้อ ...` ในโหมดแบ่งกิจกรรมตามตัวชี้วัดย่อย

## การทดสอบ

- เพิ่ม regression test ตรวจว่าปุ่มในโหมดกิจกรรมเพิ่มเติมอยู่หลัง `data-support-activity-container`
- ยืนยันว่าปุ่มยังมี `data-add-support-activity` และแสดงตามสิทธิ์เดิม
- ยืนยันว่าโหมดแบ่งตามตัวชี้วัดย่อยยังวางปุ่มของแต่ละข้อไว้ตำแหน่งเดิม
- รัน focused feature test, Blade view cache, frontend build และ `git diff --check`

## เกณฑ์สำเร็จ

ในโหมด `กิจกรรม/โครงการเพิ่มเติม` ผู้ใช้เห็นปุ่ม `+ เพิ่มกิจกรรม/โครงการ` ชิดซ้ายใต้การ์ดรายการสุดท้ายและส่วนหลักฐาน หรือใต้ข้อความสถานะว่างเมื่อยังไม่มีรายการ โดยการเพิ่มรายการและโหมดแบ่งตามตัวชี้วัดทำงานเหมือนเดิม
