# ซ่อนประวัติการแก้ไขคะแนนของผู้ถูกประเมิน

วันที่: 26 กรกฎาคม 2026

## เป้าหมาย

ไม่แสดงประวัติการแก้ไขคะแนนที่ผู้ถูกประเมินเป็นผู้แก้เองในหน้าจอของผู้ใช้งานทุกบทบาท แต่ยังคงบันทึกข้อมูลดังกล่าวไว้ในตารางประวัติเพื่อใช้เป็น audit log

การเปลี่ยนแปลงนี้ครอบคลุมข้อมูลย้อนหลังและคะแนนทุกประเภท:

- คะแนนปริมาณ
- คะแนนคุณภาพ
- คะแนนสายสนับสนุน
- คะแนนและข้อมูลกิจกรรมหรือโครงการสายสนับสนุน

## พฤติกรรมที่ต้องการ

เมื่อระบบเตรียมประวัติคะแนนสำหรับส่งไปแสดง จะไม่นำรายการต่อไปนี้ไปแสดง:

1. รายการที่ `modifier_user_id` ตรงกับ `evaluatee_id` ของรายงาน
2. รายการเดิมที่ไม่มีทั้งผู้แก้และบทบาทผู้แก้ กล่าวคือ `modifier_user_id` และ `modifier_role` เป็น `null` ทั้งคู่

เงื่อนไขข้อ 2 รองรับข้อมูลเดิมและเส้นทางบันทึกคะแนนปริมาณของผู้ถูกประเมิน ซึ่งไม่ได้ระบุผู้แก้และบทบาทไว้ในรายการประวัติ

ประวัติที่แก้โดยผู้ประเมิน หัวหน้า หรือผู้บริหารยังแสดงตามเดิม รวมถึงกรณีที่บัญชีผู้แก้ถูกลบในภายหลังแต่ `modifier_role` ของรายการยังมีค่า

## แนวทางการออกแบบ

เพิ่มกติกากลางสำหรับคัดประวัติที่แสดงได้ และใช้กติกาเดียวกันในจุดเตรียมข้อมูลของ:

- `DashboardEvaluateeController` สำหรับหน้าของผู้ถูกประเมิน
- `ReportDataService` สำหรับหน้าของผู้ตรวจประเมินและผู้บริหาร
- `SupportCriteriaReadModel` สำหรับคะแนนและกิจกรรมสายสนับสนุน

การกรองเกิดก่อนแปลงรายการประวัติเป็น array สำหรับ view เพื่อให้ component และ JavaScript ได้รับเฉพาะรายการที่อนุญาตให้แสดง และไม่ต้องทำซ้ำกติกาในหลายหน้าจอ

กติกากลางรับข้อมูลผู้แก้ บทบาทผู้แก้ และรหัสผู้ถูกประเมิน แล้วตัดสินว่ารายการนั้นแสดงได้หรือไม่ กติกานี้ไม่มีการแก้ไขหรือลบ record ในฐานข้อมูล

## การไหลของข้อมูล

1. การบันทึกคะแนนทำงานเหมือนเดิมและสร้าง record ในตาราง history ตามเดิม
2. เมื่อเปิดหน้าประเมิน ระบบอ่าน history ของรายงานจากฐานข้อมูล
3. ระบบนำแต่ละรายการผ่านกติกากลาง
4. รายการของผู้ถูกประเมินและรายการเดิมแบบ `null/null` ถูกตัดออกจากข้อมูลสำหรับแสดงผล
5. รายการของผู้ตรวจประเมินถูกส่งต่อไปยัง Blade component หรือ JavaScript ตามเดิม

## ขอบเขตที่ไม่เปลี่ยน

- ไม่ลบหรือแก้ไขข้อมูล history เดิม
- ไม่หยุดการสร้าง history ใหม่
- ไม่เปลี่ยน schema ฐานข้อมูล
- ไม่เปลี่ยนการตรวจเหตุผลเมื่อผู้ตรวจประเมินแก้คะแนน
- ไม่เปลี่ยนสิทธิ์การแก้ไขคะแนน

## การทดสอบ

เพิ่ม regression tests เพื่อยืนยันว่า:

1. การแก้ไขโดยผู้ถูกประเมินยังสร้าง audit record ในฐานข้อมูล
2. ประวัติของผู้ถูกประเมินที่มี `modifier_user_id` ไม่ถูกส่งไปแสดง
3. ประวัติเดิมแบบ `modifier_user_id = null` และ `modifier_role = null` ไม่ถูกส่งไปแสดง
4. ประวัติของผู้ประเมิน หัวหน้า และผู้บริหารยังถูกส่งไปแสดง
5. กติกาครอบคลุมคะแนนปริมาณ คะแนนคุณภาพ คะแนนสายสนับสนุน และประวัติกิจกรรมสายสนับสนุน

## เกณฑ์สำเร็จ

- หน้าประวัติไม่แสดงรายการที่ผู้ถูกประเมินแก้เอง ไม่ว่าผู้เปิดหน้าจะมีบทบาทใด
- รายการย้อนหลังที่เข้าเงื่อนไขถูกซ่อนด้วย
- audit log ยังคงอยู่ในฐานข้อมูลครบถ้วน
- ประวัติการแก้ไขโดยผู้ตรวจประเมินยังแสดงถูกต้อง
