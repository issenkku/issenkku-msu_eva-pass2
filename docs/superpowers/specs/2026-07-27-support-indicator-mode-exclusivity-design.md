# Support Indicator Mode Exclusivity

## เป้าหมาย

ทำให้รูปแบบการกำหนดตัวชี้วัดของเกณฑ์สายสนับสนุนมีสถานะที่ชัดเจนและไม่ขัดกัน:

1. ผู้ดูแลกำหนดตัวชี้วัดย่อยและแยกโครงการตามข้อย่อย
2. ผู้ถูกประเมินกรอกตัวชี้วัดของแต่ละโครงการเอง

สองรูปแบบนี้ต้องไม่เปิดพร้อมกัน และการเปลี่ยนจากรูปแบบแรกไปเป็นรูปแบบที่สองต้องไม่ลบโครงการหรือความสัมพันธ์เดิม

## กติกาหน้าตั้งค่า

- ตัวเลือก “แยกโครงการตามตัวชี้วัดย่อย” และ “อนุญาตให้ผู้ถูกประเมินกรอกตัวชี้วัด” เป็น mutually exclusive
- เมื่อเลือก “อนุญาตให้ผู้ถูกประเมินกรอกตัวชี้วัด”:
  - ยกเลิกการเลือก “แยกโครงการตามตัวชี้วัดย่อย”
  - ปิดการใช้งาน checkbox ของโหมดแยกโครงการ
  - ซ่อนส่วนตั้งค่าตัวชี้วัดย่อย
- เมื่อเลือก “แยกโครงการตามตัวชี้วัดย่อย”:
  - “อนุญาตให้ผู้ถูกประเมินกรอกตัวชี้วัด” ต้องไม่ถูกเลือก
  - ปิดการใช้งาน checkbox ให้ผู้ถูกประเมินกรอกตัวชี้วัด
- หากเปิดข้อมูลเดิมที่มีสองค่าเป็นจริงพร้อมกัน ให้ UI ใช้โหมดผู้ถูกประเมินกรอกตัวชี้วัดเป็นหลักและยกเลิกโหมดแยกโครงการก่อนส่งข้อมูล
- ทั้งสองตัวเลือกยังขึ้นกับ “อนุญาตให้ผู้ถูกประเมินเพิ่มกิจกรรม/โครงการ” เหมือนเดิม หากปิดการเพิ่มโครงการต้องยกเลิกและปิดการใช้งานทั้งสองตัวเลือก

พฤติกรรมนี้ต้องเหมือนกันทั้งหน้าสร้างและหน้าแก้ไขเกณฑ์

## กติกาฝั่ง Server

- ปฏิเสธ request ที่ส่ง `allow_evaluatee_indicator = true` และ `group_activity_entries_by_indicator = true` พร้อมกัน แม้ client จะไม่ใช่ UI ของระบบ
- ยกเลิก validation ที่ห้ามปิดโหมดแยกโครงการเพียงเพราะมีโครงการอ้างอิงตัวชี้วัดย่อย
- ยังคง validation ที่ห้ามลบตัวชี้วัดย่อยซึ่งมีโครงการอ้างอิง
- การเปลี่ยนจากโหมดแยกโครงการไปเป็นโหมดผู้ถูกประเมินกรอกตัวชี้วัดต้องทำภายใน transaction เดิมของการอัปเดตโครงสร้างรายงาน

## การรักษาข้อมูลเดิม

เมื่อปิดโหมดแยกโครงการ:

- ไม่ลบแถว `support_indicator_items`
- ไม่ล้าง `support_activity_entries.support_indicator_item_id`
- โครงการเดิมแสดงรวมเป็นรายการเดียวตาม read model ของโหมดไม่แยก
- ผู้ถูกประเมินกรอก `indicator` ของแต่ละโครงการและบันทึกได้ตามกติกาปัจจุบัน
- Backend ยอมรับ `support_indicator_item_id` ที่ซ่อนไว้เฉพาะโครงการเดิม เมื่อ ID ที่ส่งมาตรงกับค่าที่บันทึกอยู่และเป็นของเกณฑ์เดิม
- โครงการใหม่ที่สร้างขณะไม่แยกต้องมี `support_indicator_item_id = null`
- ห้ามเปลี่ยนหรือปลอม `support_indicator_item_id` ของโครงการเดิมผ่าน request

แนวทางนี้รักษาข้อมูลและทำให้การแสดงผลแบบรวมไม่ติด validation ในการบันทึกครั้งถัดไป

## การเปิดโหมดแยกกลับ

- หากทุกโครงการมี `support_indicator_item_id` เดิมครบ สามารถเปิดโหมดแยกกลับและแสดงกลุ่มเดิมได้
- หากมีโครงการที่สร้างในช่วงไม่แยกและมี `support_indicator_item_id = null` ให้ปฏิเสธการเปิดโหมดแยก
- ข้อความ validation ต้องอธิบายว่ามีโครงการที่ยังไม่ได้สังกัดตัวชี้วัดย่อยและต้องจัดการก่อน
- ระบบไม่เลือกข้อย่อยให้โครงการโดยอัตโนมัติ เพราะอาจเปลี่ยนความหมายของข้อมูล

## Data flow

1. ผู้ดูแลเลือกให้ผู้ถูกประเมินกรอกตัวชี้วัด
2. UI ยกเลิกและปิดโหมดแยกโครงการ แล้วส่งค่าที่ไม่ขัดกัน
3. Controller ตรวจ mutual exclusion และส่งข้อมูลเข้า transaction อัปเดตโครงสร้าง
4. `SupportIndicatorItemService` ปล่อยให้ปิดโหมดโดยคงข้อย่อยและความสัมพันธ์เดิม
5. Read model แสดงโครงการเดิมแบบรายการรวม
6. เมื่อบันทึกผลประเมิน `SupportActivityEntryService` ยืนยันว่าความสัมพันธ์ที่ซ่อนไว้ของโครงการเดิมไม่ถูกเปลี่ยน และอนุญาตให้บันทึกตัวชี้วัดรายโครงการ

## การทดสอบ

- UI contract test สำหรับหน้าสร้างและหน้าแก้ไขยืนยันว่า checkbox ทั้งสองเป็น mutually exclusive
- UI contract test ยืนยันว่าข้อมูลเดิมที่มีสองโหมดพร้อมกันถูก normalize โดยให้โหมดผู้ถูกประเมินกรอกตัวชี้วัดเป็นหลัก
- Feature test ปฏิเสธ request สร้างและแก้ไขที่เปิดสองโหมดพร้อมกัน
- Feature test ยืนยันว่า Admin เปลี่ยนจากโหมดแยกเป็นโหมดผู้ถูกประเมินกรอกได้แม้มีโครงการอ้างอิง
- Feature test ยืนยันว่าข้อย่อย โครงการ หลักฐาน และ `support_indicator_item_id` เดิมยังอยู่ครบหลังเปลี่ยนโหมด
- Evaluation/service test ยืนยันว่าโครงการเดิมบันทึกตัวชี้วัดรายโครงการได้โดยคง hidden association เดิม
- Evaluation/service test ปฏิเสธการเปลี่ยน hidden association และปฏิเสธการส่ง association ให้โครงการใหม่ในโหมดไม่แยก
- Feature test ยืนยันว่าเปิดโหมดแยกกลับได้เมื่อทุกโครงการยังมี association
- Feature test ปฏิเสธการเปิดกลับเมื่อมีโครงการ `support_indicator_item_id = null`
- Regression test ยืนยันว่าการลบข้อย่อยที่มีโครงการอ้างอิงยังถูกปฏิเสธ

## นอกขอบเขต

- ไม่สร้างหน้าจอสำหรับย้ายโครงการระหว่างตัวชี้วัดย่อย
- ไม่กำหนดตัวชี้วัดย่อยให้โครงการแบบอัตโนมัติ
- ไม่ลบหรือ migrate โครงการ หลักฐาน ประวัติ หรือข้อย่อยเดิม
- ไม่เปลี่ยนสูตรคะแนน น้ำหนัก สถานะรายงาน หรือสิทธิ์ตาม workflow
