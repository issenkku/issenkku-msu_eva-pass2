# Subject Name Flexibility Design

**วันที่:** 2026-07-17  
**สถานะ:** อนุมัติแล้ว  
**ขอบเขต:** ชื่อรายวิชาในการนำเข้า Excel และฟอร์มเพิ่ม/แก้ไขรายวิชา

## ความสัมพันธ์กับเอกสารเดิม

เอกสารนี้แก้ไขและใช้แทนกติกาเรื่อง `name_th` และ `name_en` ใน
`2026-07-17-subject-excel-import-design.md` เฉพาะส่วนชื่อรายวิชา ส่วนกติกาอื่นของการนำเข้า Excel
รวมถึงการตรวจหน่วยกิตยังคงเดิม

## ปัญหา

ข้อมูลรายวิชาบางชุดมีเฉพาะชื่อภาษาอังกฤษ แต่ระบบปัจจุบันบังคับ `name_th` และจำกัดทั้งสองชื่อไว้ที่
255 ตัวอักษร ทำให้ข้อมูลที่มีชื่ออังกฤษอย่างเดียวหรือชื่อยาวถูกปฏิเสธ แม้จะมีชื่อรายวิชาที่ใช้งานได้อยู่แล้ว

## เป้าหมาย

- รายวิชาต้องมีชื่ออย่างน้อยหนึ่งช่องระหว่างชื่อไทยกับชื่ออังกฤษ
- ไม่บังคับว่าชื่อต้องเป็นภาษาใด และไม่จำกัดความยาวใน validation ของแอปพลิเคชัน
- ใช้กติกาเดียวกันกับการนำเข้า Excel และฟอร์มเพิ่ม/แก้ไข
- เก็บชื่อในช่องภาษาที่ผู้ใช้ระบุจริง โดยไม่คัดลอกชื่อข้ามช่อง
- หน้าจอเดิมยังแสดง ค้นหา และเรียงรายวิชาที่ไม่มีชื่อไทยได้

## สิ่งที่ไม่อยู่ในขอบเขต

- ไม่เปลี่ยนหัวคอลัมน์ Excel
- ไม่เดาภาษาจากตัวอักษรที่ผู้ใช้กรอก
- ไม่เปลี่ยนกติกาการตรวจรหัสรายวิชา
- ไม่เปลี่ยนกติกาหรือรูปแบบหน่วยกิต
- ไม่เพิ่มช่องชื่อหลักช่องที่สาม

## กติกาข้อมูล

### การทำความสะอาดค่า

- ตัดช่องว่างหัวท้ายของ `name_th` และ `name_en`
- ค่าว่างหรือค่าที่มีแต่ช่องว่างแปลงเป็น `null`
- หลังทำความสะอาดแล้ว ต้องมีค่าอย่างน้อยหนึ่งช่อง
- ไม่มี `max:255` หรือข้อจำกัดชุดภาษาใน application validation

### ฐานข้อมูล

- เปลี่ยน `subjects.name_th` จาก `VARCHAR(255) NOT NULL` เป็น `TEXT NULL`
- เปลี่ยน `subjects.name_en` จาก `VARCHAR(255) NULL` เป็น `TEXT NULL`
- migration ต้องรักษาข้อมูลเดิมทั้งหมด
- การ rollback จะทำได้เฉพาะเมื่อไม่มีแถวที่มีชื่อยาวเกิน 255 ตัวอักษรและไม่มีแถวที่มีเฉพาะชื่ออังกฤษ
  หากข้อมูลไม่เข้ากับ schema เดิม ให้หยุด rollback พร้อมข้อความชัดเจนแทนการตัดหรือคัดลอกข้อมูลโดยอัตโนมัติ

กติกาอย่างน้อยหนึ่งชื่อบังคับที่ทุก write boundary ของแอปพลิเคชัน เพื่อให้ทำงานเหมือนกันทั้ง HTTP form
และ Excel import โดยไม่ผูก migration กับ check-constraint เฉพาะฐานข้อมูลชนิดใดชนิดหนึ่ง

## ฟอร์มเพิ่มและแก้ไข

- เอาเครื่องหมายบังคับออกจากชื่อไทยเพียงช่องเดียว
- แสดงคำแนะนำว่า “กรอกชื่อรายวิชาภาษาไทยหรือภาษาอังกฤษอย่างน้อยหนึ่งช่อง”
- เมื่อทั้งสองช่องว่าง ให้แสดงข้อผิดพลาดระดับกลุ่มด้วยข้อความเดียวกันและไม่ส่งข้อมูล
- เมื่อมีอย่างน้อยหนึ่งช่อง ให้ยอมรับข้อความทุกภาษาและทุกความยาวที่ฐานข้อมูล `TEXT` รองรับ
- request validation ฝั่งเซิร์ฟเวอร์ใช้กติกาเดียวกับ JavaScript และเป็นผู้ตัดสินสุดท้าย

## การนำเข้า Excel

- คอลัมน์ B `ชื่อรายวิชา (ไทย)` และ C `ชื่อรายวิชา (อังกฤษ)` ไม่บังคับแยกช่อง
- แต่ละแถวต้องมีค่าใน B หรือ C อย่างน้อยหนึ่งช่อง
- หากว่างทั้งคู่ ให้สร้างข้อผิดพลาดหนึ่งรายการที่อธิบายว่าต้องกรอกอย่างน้อยหนึ่งชื่อ
- ไม่ตรวจความยาว 255 ตัวอักษร
- หน้า preview ใช้ชื่อที่มีอยู่ จึงต้องรองรับแถวที่ `name_th` เป็น `null`
- การอัปเดตข้อมูลซ้ำใช้ค่าจากทั้งสองช่องตามไฟล์ ค่าว่างในช่องใดหมายถึงล้างค่าของช่องนั้น
- การส่งออกเก็บ `name_th` และ `name_en` ตามช่องจริง ไม่เติมค่าทดแทนลงในไฟล์
- แผ่นงาน “คำแนะนำ” ระบุกติกาใหม่และเอาข้อความจำกัด 255 ตัวอักษรออก

## การแสดงผล ค้นหา และเรียงลำดับ

เพิ่มแนวคิด `display_name` ให้รายวิชา โดยเลือกค่าตามลำดับ:

1. `name_th` เมื่อมีค่า
2. `name_en` เมื่อไม่มีชื่อไทย

ตารางรายวิชา, ข้อความ accessible, หน้า preview และจุดแสดงชื่อรายวิชาที่เกี่ยวข้องต้องใช้
`display_name` เป็นชื่อหลัก ชื่ออังกฤษบรรทัดรองจะแสดงเฉพาะเมื่อมีชื่อไทยและชื่ออังกฤษทั้งคู่ เพื่อไม่แสดงชื่อเดิมซ้ำ

การค้นหายังค้นทั้ง `name_th` และ `name_en` การเรียงตามชื่อใช้ชื่อไทยเมื่อมี มิฉะนั้นใช้ชื่ออังกฤษ
ด้วยนิพจน์ที่รองรับฐานข้อมูลของระบบและมี `code` เป็นตัวตัดสินลำดับเมื่อชื่อเท่ากัน

## ความเข้ากันได้กับข้อมูลเดิม

- แถวเดิมมี `name_th` อยู่แล้ว จึงไม่ต้องแปลงค่าข้อมูล
- API และ view ต้องไม่สมมติว่า `name_th` เป็น string เสมอหลัง migration
- จุดที่สร้าง payload สำหรับ modal หรือการประเมินต้องส่งค่า `null`/ค่าว่างได้โดยไม่เกิด error
- ไม่มีการคัดลอกชื่ออังกฤษลง `name_th` ย้อนหลัง

## การจัดการข้อผิดพลาด

- ฟอร์ม: ปฏิเสธเมื่อทั้งสองชื่อว่างและคงค่าที่ผู้ใช้กรอกไว้
- Excel: ระบุเลขแถวและสาเหตุ “ต้องกรอกชื่อรายวิชาภาษาไทยหรือภาษาอังกฤษอย่างน้อยหนึ่งช่อง”
- ข้อผิดพลาดชื่อไม่ปิดบังข้อผิดพลาดฟิลด์อื่นในแถวเดียวกัน
- หาก migration หรือ rollback ไม่สามารถรักษาข้อมูลได้ ต้องหยุดโดยไม่แก้ข้อมูลบางส่วน

## การทดสอบ

เพิ่มหรือปรับการทดสอบให้ครอบคลุม:

- เพิ่มและแก้ไขรายวิชาที่มีเฉพาะชื่อไทย
- เพิ่มและแก้ไขรายวิชาที่มีเฉพาะชื่ออังกฤษ
- ปฏิเสธฟอร์มที่ว่างทั้งสองชื่อ
- ยอมรับชื่อที่ยาวเกิน 255 ตัวอักษรจากฟอร์มและ Excel
- นำเข้า preview และ confirm แถวที่มีเฉพาะชื่ออังกฤษ
- ปฏิเสธแถว Excel ที่ว่างทั้งสองชื่อพร้อมเลขแถวและข้อความที่ถูกต้อง
- แสดงชื่ออังกฤษเป็นชื่อหลักเมื่อไม่มีชื่อไทย
- ค้นหาและเรียงรายวิชาที่มีเฉพาะชื่ออังกฤษ
- ส่งออกแล้วช่องภาษายังคงตรงกับข้อมูลจริง
- regression tests ของการนำเข้า Excel และการจัดการรายวิชาเดิมยังผ่าน

## เกณฑ์ยอมรับ

งานเสร็จเมื่อผู้ดูแลระบบสามารถเพิ่ม แก้ไข หรือนำเข้ารายวิชาที่มีชื่อเพียงภาษาใดภาษาหนึ่งได้
ชื่อที่ยาวเกิน 255 ตัวอักษรถูกบันทึกครบ และทุกหน้าที่เกี่ยวข้องแสดงชื่อที่มีอยู่โดยไม่เกิดช่องว่างหรือ error
ขณะเดียวกันระบบยังปฏิเสธรายวิชาที่ไม่มีชื่อทั้งสองช่อง
