# Support Criteria Conditional Row Layout Design

## Goal

ปรับตารางเกณฑ์สายสนับสนุนให้แยกหัวข้อที่แอดมินกำหนดออกจากรายการย่อยอย่างชัดเจน และแบ่งแถวเฉพาะข้อมูลที่ผู้ถูกประเมินต้องกรอกแยกตามกิจกรรม โดยไม่เปลี่ยนกติกาการคำนวณ การบันทึกคะแนน หรือโครงสร้างฐานข้อมูล

## Visual hierarchy

- แสดง `activity_name` ซึ่งเป็นหัวข้อที่แอดมินกำหนดเป็นข้อความสีดำ น้ำหนักตัวอักษรหนา และวางเต็มแถวเหนือรายการย่อย
- ไม่แสดงป้าย ไอคอน หรือข้อความ “หัวข้อที่แอดมินกำหนด”
- แสดงกิจกรรมย่อยด้วยเลขลำดับวงกลมและข้อความสีน้ำตาลเดิม เพื่อแยกจากหัวข้อหลัก
- เส้นแบ่งแนวนอนต้องปรากฏเฉพาะคอลัมน์ที่มีข้อมูลแยกตามกิจกรรม ไม่ลากผ่านเซลล์ที่ใช้ร่วมกัน
- เซลล์ที่ใช้ร่วมกันต้องรวมความสูงด้วย `rowspan` และจัดค่าไว้กึ่งกลางกลุ่ม เพื่อไม่ให้ค่า ปุ่ม หรือเครื่องหมายขีดดูลอยอยู่ในแถวใดแถวหนึ่ง

## Conditional rendering rules

ตารางต้องตัดสินการแบ่งเซลล์จากค่ากำหนดของเกณฑ์แต่ละข้อ ไม่ใช้รูปแบบเดียวกับทุกข้อ

| คอลัมน์ | เงื่อนไขการแสดง |
| --- | --- |
| ลำดับ | ใช้ร่วมกันทั้งหัวข้อ |
| กิจกรรม/โครงการ/งาน | แยกตาม `activity_entries` เมื่อเปิด `allow_activity_entries` |
| ตัวชี้วัด/เกณฑ์การประเมิน | แยกตามกิจกรรมเมื่อ `allow_evaluatee_indicator` เป็นจริง มิฉะนั้นใช้ค่าที่แอดมินกำหนดร่วมกัน |
| ระดับค่าเป้าหมาย | ใช้ร่วมกันทั้งหัวข้อ |
| น้ำหนัก | แยกตามกิจกรรมเมื่อ `allow_evaluatee_weight` เป็นจริง มิฉะนั้นใช้ `weight` ระดับหัวข้อร่วมกัน |
| ค่าคะแนนที่ได้ | แยกตามกิจกรรมเมื่อ `allow_evaluatee_weight` เป็นจริง มิฉะนั้นใช้ `achieved_score` ระดับหัวข้อร่วมกัน |
| คะแนนถ่วงน้ำหนัก | แสดงผลรวมระดับหัวข้อร่วมกัน โดยคงสูตรคำนวณเดิม |
| ประวัติการแก้ไข | ใช้พื้นที่ร่วมของหัวข้อและเปิดรายละเอียดตามข้อมูลประวัติเดิม |
| หลักฐาน | ใช้พื้นที่ร่วมของหัวข้อ แต่ต้องคงหลักฐานของแต่ละกิจกรรมครบถ้วนและระบุรายการย่อยที่หลักฐานนั้นสังกัด |
| จัดการ | ใช้ปุ่มระดับหัวข้อร่วมกันหนึ่งปุ่ม |

### Resulting modes

1. ถ้าเปิดให้เพิ่มกิจกรรมและกรอกตัวชี้วัดเอง แต่ไม่เปิดให้กรอกน้ำหนักเอง ตารางจะแบ่งเฉพาะกิจกรรมและตัวชี้วัด น้ำหนักกับค่าคะแนนจะแสดงครั้งเดียว
2. ถ้าเปิดให้กรอกน้ำหนักเอง ตารางจะแบ่งกิจกรรม ตัวชี้วัดที่ผู้ใช้กรอกเอง น้ำหนัก และค่าคะแนนตามแต่ละกิจกรรม
3. ถ้าไม่มีรายการย่อย ตารางใช้รูปแบบแถวเดี่ยวเดิม

## Architecture and data flow

การเปลี่ยนแปลงอยู่ในชั้นแสดงผล:

- `SupportCriteriaReadModel` ยังคงส่งค่าระดับหัวข้อและ `activity_entries` ตามเดิม
- `support-criteria-table.blade.php` เลือกว่าจะสร้างเซลล์ร่วม (`rowspan`) หรือเซลล์รายกิจกรรมจากแฟล็ก `allow_evaluatee_indicator` และ `allow_evaluatee_weight`
- `support-criteria-table-script.blade.php` อัปเดตเฉพาะเป้าหมาย DOM ที่มีอยู่ในโหมดนั้น และต้องไม่สร้างค่ารายกิจกรรมในคอลัมน์ที่เป็นค่าร่วม
- `SupportActivityEntryService`, `SupportScoreService` และสูตร `SupportWeightedScore` ไม่เปลี่ยนแปลง

ไม่มี migration, API contract หรือ payload ใหม่ ข้อมูลที่ผู้ใช้กรอกยังถูกส่งไปยังช่องระดับหัวข้อหรือ `activity_entries` ตามแฟล็กเดิม

## Evidence and history behavior

การรวมเซลล์เป็นการรวมพื้นที่แสดงผลเท่านั้น:

- หลักฐานรายกิจกรรมต้องไม่ถูกทิ้งหรือรวมจนระบุเจ้าของไม่ได้
- ในเซลล์หลักฐานร่วม ให้จัดกลุ่มลิงก์ตามลำดับกิจกรรมและคง `aria-label` ที่ระบุรายการ
- ประวัติระดับกิจกรรมและระดับหัวข้อต้องยังเปิดดูได้จากพื้นที่ประวัติร่วม โดยไม่เปลี่ยนกติกาการมองเห็นประวัติ

## Responsive behavior

- Desktop ใช้หัวข้อเต็มแถวและ `rowspan` ตามกติกาข้างต้น
- Mobile card ต้องใช้ลำดับชั้นเดียวกัน: หัวข้อแอดมินสีดำอยู่บนสุด ตามด้วยกิจกรรมย่อย และสรุปค่าร่วมเพียงครั้งเดียว
- ในโหมดที่น้ำหนักเป็นรายกิจกรรม ให้แสดงน้ำหนักและค่าคะแนนใต้กิจกรรมนั้น ไม่ย้ายไปอยู่ในสรุปค่าร่วม

## Accessibility

- หัวข้อแอดมินใช้ `<th scope="rowgroup">`
- รายการย่อยรักษาลำดับการอ่านตาม DOM
- เซลล์ร่วมต้องไม่ทำให้โปรแกรมอ่านหน้าจอประกาศค่าซ้ำ
- ปุ่มและลิงก์หลักฐานคงชื่อที่อธิบายหัวข้อหรือกิจกรรมเป้าหมาย
- สีดำและสีน้ำตาลเป็นตัวช่วยด้านลำดับชั้น ไม่ใช่สัญญาณเพียงอย่างเดียว

## Testing

เพิ่มหรือปรับ view tests ให้ครอบคลุม:

1. หัวข้อแอดมินเป็น `rowgroup` เต็มแถวและไม่มีข้อความป้ายกำกับ
2. โหมดกรอกเฉพาะตัวชี้วัดสร้างเซลล์กิจกรรมและตัวชี้วัดตามจำนวนรายการ แต่สร้างน้ำหนักและค่าคะแนนระดับหัวข้อเพียงหนึ่งเซลล์
3. โหมดกรอกน้ำหนักเองสร้างน้ำหนักและค่าคะแนนตามจำนวนรายการ
4. คะแนนถ่วงน้ำหนักรวม ปุ่มจัดการ และลำดับใช้ `rowspan` เท่าจำนวนรายการ
5. หลักฐานจากทุกรายการยังแสดงครบและระบุรายการเจ้าของ
6. JavaScript อัปเดตทั้งโหมดค่าร่วมและโหมดค่ารายกิจกรรมได้ถูกต้อง
7. รูปแบบแถวเดี่ยวและ mobile card ไม่ถดถอย

รันชุดทดสอบเฉพาะ `SupportCriteriaEvaluationViewTest` ก่อน แล้วรันชุดทดสอบที่เกี่ยวข้องกับการอ่านข้อมูลและการคำนวณคะแนนเพื่อยืนยันว่า Logic เดิมไม่เปลี่ยน

## Non-goals

- ไม่เปลี่ยนสูตรคะแนนหรือนิยามคะแนนถ่วงน้ำหนัก
- ไม่เปลี่ยนสิทธิ์ว่าใครกรอกตัวชี้วัด น้ำหนัก หรือคะแนน
- ไม่ย้ายข้อมูลระหว่างระดับหัวข้อกับระดับกิจกรรม
- ไม่เปลี่ยน schema ฐานข้อมูลหรือ API
