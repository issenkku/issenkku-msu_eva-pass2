# Support Criteria Modal Management Design

วันที่: 2026-07-20  
สถานะ: อนุมัติแนวทางแล้ว รอตรวจทานเอกสารก่อนพัฒนา

## เป้าหมาย

ปรับหน้ากรอกคะแนนเกณฑ์สายสนับสนุนให้ตารางเป็นจุดเริ่มต้นของทุกการทำงาน ลดความยาวของหน้าโดยย้ายฟอร์มคะแนน หลักฐาน เหตุผล และประวัติจากการ์ดใต้ตารางเข้า Modal กลางหนึ่งชุด โดยไม่เปลี่ยนกติกาการบันทึกหรือ Flow การประเมินเดิม

## ขอบเขต

- เพิ่มคอลัมน์ `หลักฐาน` ในตารางและการ์ดมือถือ
- เพิ่มคอลัมน์ `จัดการ` เฉพาะหน้าหรือสถานะที่แก้ไขข้อมูลได้
- ลบชุดการ์ดฟอร์มที่แสดงต่อท้ายตาราง
- ใช้ Modal กลางหนึ่งชุดสำหรับกรอกหรือแก้ไขข้อมูลทีละรายการ
- ใช้ Modal เดียวกันในโหมดดูหลักฐานอย่างเดียว
- ไม่เพิ่ม API หรือการบันทึกฐานข้อมูลจาก Modal
- ไม่เปลี่ยนกติกาคะแนน หลักฐาน เหตุผล ประวัติ หรือสิทธิ์ของแต่ละ Role

## โครงสร้างตาราง

ตารางเดสก์ท็อปเรียงคอลัมน์ดังนี้:

1. ลำดับ
2. กิจกรรม/โครงการ/งาน
3. ตัวชี้วัด/เกณฑ์การประเมิน
4. ระดับค่าเป้าหมาย
5. น้ำหนัก
6. ค่าคะแนนที่ได้
7. คะแนนถ่วงน้ำหนัก
8. หลักฐาน
9. จัดการ เฉพาะเมื่อรายการแก้ไขได้

คอลัมน์หลักฐานแสดงจำนวน เช่น `2 ลิงก์` เป็นปุ่มที่เปิด Modal เพื่อดูรายการ URL หากไม่มีหลักฐานให้แสดง `ไม่มีหลักฐาน` โดยไม่สร้างปุ่มว่าง

คอลัมน์จัดการแสดงปุ่ม `กรอกข้อมูล` เมื่อยังไม่มีคะแนนหรือหลักฐาน และ `แก้ไขข้อมูล` เมื่อรายการมีข้อมูลแล้ว ในโหมดอ่านอย่างเดียวจะไม่แสดงคอลัมน์นี้

## การแสดงผลบนมือถือ

คงรูปแบบการ์ดสรุปรายการเดิม แต่เพิ่ม:

- จำนวนหลักฐานที่กดดูได้
- ปุ่ม `กรอกข้อมูล` หรือ `แก้ไขข้อมูล` เมื่อสถานะอนุญาต

จะไม่มีฟอร์มคะแนนหรือหลักฐานยาวต่อท้ายรายการบนมือถือหรือเดสก์ท็อป

## Modal กลาง

หน้าเว็บมี Modal กลางเพียงหนึ่งชุด เนื้อหาถูกผูกกับรายการที่ผู้ใช้เลือก โดย Modal แสดงข้อมูลตามสิทธิ์เดิม:

- ชื่อลำดับและกิจกรรม
- ช่องค่าคะแนนที่ได้เมื่อ Role แก้ไขคะแนนได้
- คะแนนถ่วงน้ำหนักที่คำนวณสดจากน้ำหนักของรายการ
- รายการ URL หลักฐาน พร้อมเพิ่มและลบเมื่อ Role แก้ไขหลักฐานได้
- หลักฐานแบบอ่านอย่างเดียวเมื่อ Role ไม่มีสิทธิ์แก้ไขหลักฐาน
- เหตุผลการแก้ไขคะแนนเมื่อ Role ปัจจุบันต้องระบุเหตุผล
- ประวัติการแก้ไขคะแนนเมื่อมีข้อมูล

Modal มีปุ่ม `บันทึก` และ `ยกเลิก` พร้อมปุ่มปิด มอบ focus ให้หัวข้อหรือช่องแรกเมื่อเปิด ล็อกการเลื่อนด้านหลัง และรองรับการปิดด้วย `Esc` รวมถึงการใช้งานด้วยคีย์บอร์ด

## พฤติกรรมการบันทึก

ช่องกรอกจริงยังเป็นส่วนหนึ่งของฟอร์มหลักและใช้ชื่อ `support_list[...]` เดิม

เมื่อกด `บันทึก` ใน Modal:

1. ตรวจรูปแบบคะแนนและ URL ของรายการปัจจุบัน
2. ตรวจหลักฐานบังคับตามกติกาเดิม
3. เก็บค่าไว้ใน DOM ของฟอร์มหลัก
4. อัปเดตคะแนน ค่าถ่วงน้ำหนัก จำนวนหลักฐาน และข้อความปุ่มในตาราง/การ์ด
5. ปิด Modal โดยยังไม่ส่งข้อมูลไป Server

ข้อมูลจะถูกเขียนลงฐานข้อมูลเมื่อผู้ใช้กด `บันทึกฉบับร่าง` หรือ `ยืนยันส่ง` ของหน้าหลักเท่านั้น

เมื่อกด `ยกเลิก`, ปุ่มปิด, ฉากหลัง หรือ `Esc` ระบบจะคืนคะแนน หลักฐาน และเหตุผลเป็นค่าก่อนเปิด Modal แล้วจึงปิด Modal

## การเปิด Modal จากหลักฐาน

- ในโหมดแก้ไข การกดจำนวนหลักฐานเปิด Modal ของรายการเดียวกันและเลื่อนไปส่วนหลักฐาน
- ในโหมดอ่านอย่างเดียว การกดจำนวนหลักฐานเปิด Modal แบบดูอย่างเดียว ซึ่งไม่แสดงปุ่มบันทึกหรือช่องกรอก
- ลิงก์หลักฐานแต่ละรายการเปิดแท็บใหม่และใช้ `noopener noreferrer`

## Validation และข้อผิดพลาด

กติกาเดิมยังคงอยู่:

- คะแนนต้องไม่น้อยกว่า 0 และมีทศนิยมไม่เกิน 2 ตำแหน่ง
- หลักฐานต้องเป็น HTTP หรือ HTTPS URL ที่ถูกต้อง
- รายการที่แอดมินกำหนดให้แนบหลักฐานต้องมี URL อย่างน้อยหนึ่งรายการ ทั้งการบันทึกฉบับร่างและการยืนยันส่ง
- Reviewer ที่เปลี่ยนคะแนนเดิมต้องระบุเหตุผลตาม Flow เดิม

Validation ระดับ Modal แสดงข้อความใต้ช่องที่มีปัญหาและไม่ปิด Modal ส่วน Validation ของฟอร์มหลักยังตรวจทุกเกณฑ์อีกครั้ง หากพบข้อผิดพลาดให้เปิด Modal ของรายการแรกที่ผิดและเลื่อนไปยังช่องนั้น

Server-side validation ยังคงเป็นแหล่งตัดสินสุดท้าย และต้องไม่เชื่อค่าคะแนนถ่วงน้ำหนักจาก Browser

## การคำนวณและข้อมูล

- สูตรคะแนนถ่วงน้ำหนักยังเป็น `น้ำหนัก × ค่าคะแนนที่ได้ ÷ 100`
- ตารางและ Modal แสดงค่าคำนวณเดียวกัน
- ผลรวมจริงและเพดานแสดงผลของคะแนนสายสนับสนุนยังใช้กติกาเดิม
- ไม่มีการเปลี่ยน schema, model, service หรือ controller นอกจากจำเป็นต่อการคืน validation error เดิมกลับสู่ Modal

## แนวทางองค์ประกอบและ JavaScript

- คง Blade component `support-criteria-table` เป็นเจ้าของตาราง การ์ดมือถือ และ markup ของ Modal
- คง shared script เป็นเจ้าของการเปิด/ปิด Modal การ snapshot/restore ค่า การคำนวณ และ validation
- ใช้ data attributes ผูกแถว ปุ่ม และค่าของแต่ละเกณฑ์ด้วย `support_criteria_id`
- ใช้ Modal กลางหนึ่งชุด ไม่สร้าง Modal ซ้ำตามจำนวนรายการ
- คงชื่อ input เดิมเพื่อให้ controller และ service รับ payload รูปแบบเดิม

## รูปลักษณ์

ใช้ระบบสี amber/slate และ typography เดิมของส่วนเกณฑ์สายสนับสนุน เพื่อให้ Modal เป็นส่วนต่อเนื่องของหน้า ไม่สร้าง visual language ใหม่ จุดเด่นอยู่ที่ปุ่มจัดการและกล่องคะแนนถ่วงน้ำหนักซึ่งช่วยให้เห็นผลการกรอกทันที

## การทดสอบ

- ตารางแสดงคอลัมน์หลักฐานและคอลัมน์จัดการตามโหมด
- โหมดอ่านอย่างเดียวไม่มีปุ่มจัดการหรือช่องกรอก แต่เปิดดูหลักฐานได้
- มีช่องคะแนนจริงเพียงหนึ่งชุดต่อรายการและยังใช้ชื่อ payload เดิม
- เปิด Modal จากปุ่มจัดการแล้วโหลดค่ารายการถูกต้อง
- กดบันทึกแล้วอัปเดตตาราง แต่ไม่ส่ง request ไป Server
- กดยกเลิก ปิด ฉากหลัง หรือ `Esc` แล้วคืนค่าเดิม
- เพิ่มและลบลิงก์แล้วจำนวนหลักฐานอัปเดต
- คะแนนถ่วงน้ำหนักอัปเดตทั้ง Modal ตาราง และผลรวม
- validation เปิด Modal ของรายการแรกที่ผิด
- ทุก Role ยังเห็นและแก้ไขข้อมูลตามสิทธิ์เดิม
- ชุดทดสอบการบันทึกคะแนน หลักฐาน ประวัติ Comment และ Assignment Flow เดิมต้องผ่าน

## เกณฑ์สำเร็จ

ผู้ใช้เริ่มกรอกหรือแก้ไขคะแนนสายสนับสนุนจากคอลัมน์จัดการในตาราง ใช้ Modal ทำรายการและกดบันทึกเพื่อเก็บค่าบนหน้าจอ จากนั้นใช้ปุ่มบันทึกหรือส่งของหน้าหลักตาม Flow เดิม ผู้ใช้ในโหมดอ่านอย่างเดียวเห็นคะแนนในตารางและกดจำนวนหลักฐานเพื่อดู URL ได้ โดยไม่มีฟอร์มซ้ำใต้ตารางและไม่เปลี่ยนกติกาฝั่ง Server
